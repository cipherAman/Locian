Locian User Guide & Technical Documentation

Everything you need to set up, operate, and optimize on-device language models using Locian on Android.

1. Hardware & System Requirements

Locian runs quantized GGUF models directly within the device's CPU and RAM. Because no remote servers are contacted, performance and maximum model size depend entirely on your phone's hardware specifications.

Component Minimum Specification Recommended Specification
Operating System Android 8.0 (API level 26) Android 13.0+ (API level 33+)
CPU Architecture ARM64-v8a (64-bit ARM) ARMv8.2-A or ARMv8.4-A (with DotProd / FP16 / i8mm)
System Memory (RAM) 4 GB RAM (supports 0.5B – 1B models) 8 GB – 12 GB RAM (supports 1.5B – 3B models)
Available Storage 1.5 GB free internal flash storage 5 GB+ free UFS 3.1 / 4.0 storage
Memory Allocation Notice
Android's Low-Memory Killer (LMK) terminates apps that exceed process memory caps. On a 4 GB RAM device, models larger than 1.5B parameters or context windows beyond 2048 tokens may trigger an abrupt OS shutdown.

2. Installation

Locian can be installed via pre-built debug APK or built directly from source using Android Studio.

Method A: Installing via ADB

Enable USB Debugging on your Android device (Settings → Developer Options → USB Debugging) and run:

Terminal
adb install -r app/build/outputs/apk/debug/app-debug.apk

Method B: Direct APK Sideload

Transfer app-debug.apk to your device's internal storage via USB or browser download, tap the file in your file manager, and allow "Install from unknown sources" when prompted.

Method C: Building from Source

Terminal
git clone https://github.com/Kiphra/locian.git
cd locian
./gradlew assembleDebug

3. Quickstart Workflow

Follow these three steps to begin your first offline chat session:

  1. Launch Locian: Open the application. On first boot, the hardware detection module profiles your CPU features (NEON, FP16, DotProd, i8mm) and initializes available memory ceilings.
  2. Acquire a Model: Navigate to the Models screen. Download Qwen 2.5 0.5B (ideal for fast first test) or import an existing .gguf file from storage.
  3. Activate & Chat: Tap the model card to set it as active. Return to the Chat screen, enter a prompt, and observe live streaming output with real-time decode metrics.

4. In-App Model Catalog

Locian includes a curated list of mobile-optimized GGUF models hosted on Hugging Face. The built-in download engine includes:

  • HTTP Range Resumability: If your network drops or is interrupted, resuming the download will pick up at the exact downloaded byte rather than restarting from zero.
  • SHA-256 Integrity Verification: Downloaded weights are checksum-validated to guarantee no corrupted weights reach the native engine.
  • Progress Telemetry: Live download speed (MB/s), elapsed percentage, and remaining file size.
Model Parameters Disk Size Recommended RAM Characteristics
Qwen 2.5 0.5B 0.49B ~380 MB 2 GB+ Ultra-fast token output (35–50 tok/s), lowest memory footprint.
Llama 3.2 1B 1.23B ~770 MB 3 GB+ Strong general instruction following and conversational coherence.
Qwen 2.5 1.5B 1.54B ~940 MB 4 GB+ High-accuracy code generation, mathematics, and multilingual support.
SmolLM2 1.7B 1.71B ~1.02 GB 4 GB+ Compact synthetic reasoning trained by Hugging Face.
Llama 3.2 3B 3.21B ~1.95 GB 6 GB – 8 GB Flagship on-device reasoning and complex structured output.

5. Sideloading Custom GGUF Models

You can load any compatible GGUF format model file (such as custom fine-tunes, DeepSeek R1 distillations, or specialized domain models) without using the in-app catalog.

Step 1: Download GGUF Weights

Obtain a GGUF quantized model file from Hugging Face (e.g. from communities like bartowski, unsloth, or Qwen).

Step 2: Transfer to Device

Push the file to your device's Download folder via ADB:

Terminal
adb push DeepSeek-R1-Distill-Qwen-1.5B-Q4_K_M.gguf /sdcard/Download/

Step 3: Import via File Picker

  1. In Locian, navigate to the Models screen.
  2. Tap the Import Custom Model button at the top right.
  3. Use the Android System Document Picker to select your .gguf file.
  4. Locian registers the model into its local SQLite catalog and prepares it for immediate loading.

6. Quantization Format Guidelines

When sourcing custom GGUF models, choose the quantization type that matches your device's memory bandwidth and RAM:

Quantization Bit Depth Quality / Perplexity Recommendation for Mobile
Q4_K_M 4.5 bits/weight Very High (Near FP16) Recommended sweet spot. Best balance of accuracy, memory, and speed.
Q4_0 4.0 bits/weight Standard Fastest inference on older ARMv8 cores with limited memory bandwidth.
Q5_K_M 5.5 bits/weight Maximum 5-bit Fidelity Recommended only for 1B/1.5B models on devices with 6 GB+ RAM.
Q8_0 8.0 bits/weight Virtually Identical to FP16 Not recommended on mobile due to heavy memory footprint and heat.

7. Chat Interface & Code Formatting

The chat screen supports full Markdown parsing and multi-language syntax highlighting.

Code Blocks

When the assistant generates code (e.g. Python, Kotlin, JavaScript, Rust, C++), the output is automatically enclosed in a dark-mode styled code container featuring:

  • Language badge header.
  • One-tap Copy button that copies the clean code snippet to the clipboard without metadata.
  • Horizontal scrolling for long lines without wrapping distortions.

Stop Generation

During response generation, the Send button transforms into an active Stop square. Tapping Stop instantly cancels the native inference loop and returns context control to the user.

8. Live Telemetry Pill

Beneath each assistant response, Locian renders a compact telemetry badge detailing the raw inference performance of that generation:

Metric Unit Technical Meaning
Decode Speed tok/s The token output rate during the autoregressive decoding phase: (total_tokens - 1) / decode_time_seconds.
TTFT ms Time to First Token: The total duration spent processing the prompt context before the very first token was emitted.
Total Tokens tokens The exact count of generated tokens in the assistant's reply.

9. Managing Conversations

Locian stores all conversations and message histories locally in an encrypted Room SQLite database:

  • Sidebar Drawer: Tap the hamburger menu (top left) to open your conversation history.
  • New Chat: Tap + New Chat to clear current context and begin a fresh thread.
  • Renaming: Tap the edit pencil icon next to any thread to provide a custom title.
  • Deleting: Tap the trash icon to purge a thread and its messages from local storage.

10. Inference Configuration Reference

Open the Settings screen to adjust inference hyper-parameters. Changes take effect on the very next token generation:

Parameter Range Default Recommended Function & Effect
Temperature 0.0 – 2.0 0.70 0.2 for Code / 0.7 for Chat Controls sampling randomness. 0.0 is greedy/deterministic. Higher values increase vocabulary diversity.
Top-P (Nucleus) 0.0 – 1.0 0.90 0.85 – 0.95 Restricts sampling to the smallest set of tokens whose cumulative probability reaches P.
Min-P 0.0 – 1.0 0.05 0.05 Filters out tokens with probability below (Min-P * highest_token_probability). Improves coherence.
CPU Threads 1 – Max Cores Auto Performance Cores - 1 Thread allocation for matrix math. Using all cores causes rapid thermal throttling. Set to 3 or 4 on 8-core CPUs.
Context Size 512 – 8192 2048 / 4096 2048 (4GB RAM) / 4096 (8GB+ RAM) Maximum token context window. Larger context allocates bigger KV cache in RAM.
Memory Map (mmap) On / Off On On Allows the OS to page model weights directly from storage rather than copying entire weights into RAM.
System Prompt String Helpful Assistant Task-Specific Injected system instruction defining role, formatting rules, or operational boundaries.

12. Thermal & Battery Optimization

Sustained LLM inference heavily taxes mobile CPU silicon. Follow these recommendations for optimal performance:

The "Performance Cores - 1" Rule
Most modern mobile SoCs (Snapdragon, Dimensity, Tensor) use a big.LITTLE core topology (e.g. 1 Prime + 3 Performance + 4 Efficiency cores). Setting thread count to 3 or 4 targets only the high-speed cores and leaves efficiency cores free for Android system services. This produces higher sustained tok/s and drastically delays thermal throttling.
  • Avoid Charging While Generating: Fast charging generates battery heat which triggers CPU throttling earlier.
  • Select Q4_K_M over Q8: Lower bit depth reduces memory bus traffic, conserving both battery and thermal budget.

13. Troubleshooting & FAQ

Q: The app crashes immediately when I tap a model to load it.

Cause: Out of Memory (OOM). Your device does not have enough free contiguous RAM to allocate the model weights plus KV cache.
Solution:

  • Switch to a smaller model (e.g. Qwen 2.5 0.5B or Llama 3.2 1B).
  • Reduce Context Window in Settings from 4096 down to 2048 or 1024.
  • Close background applications to free physical RAM.

Q: Generation speed starts fast, then slows down after 20 seconds.

Cause: Thermal throttling. The SoC is reducing clock frequencies to prevent overheating.
Solution: Lower the CPU Threads slider in Settings by 1 or 2 threads.

Q: My custom GGUF file isn't visible in the file picker.

Cause: The file does not have a valid lowercase .gguf extension, or Android Storage Access Framework does not have read permissions for that directory.
Solution: Ensure the file ends with .gguf and is placed in your primary /sdcard/Download/ folder.

Q: The model repeats itself in loops or generates gibberish.

Cause: Temperature is either set too high (> 1.2) or repetition penalty is needed.
Solution: Reset Temperature to 0.7 and Top-P to 0.9 in Settings.
